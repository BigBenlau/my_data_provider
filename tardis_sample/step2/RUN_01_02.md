# 五家交易所操作指南 · 01 採集、原生 CSV 匯出與 02 正規化

01 可以單獨或同時採集下列五家交易所。每家交易所有自己的 supervisor、兩個 worker，以及獨立的原始資料目錄。先用表中的服務名稱選擇交易所，再依同一批次的資料做匯出或正規化。

| 交易所 | Compose 服務與 `--exchange` | 原始批次目錄 | 資料內的市場 ID | 01 原生 channel CSV | 02 Tardis CSV |
|---|---|---|---|---|---|
| Binance | `binance` | `$DATA_ROOT/binance` | `binance` 現貨、`binance-futures` USD-M 期貨 | 支援 | 現貨 3 類、USD-M 5 類 |
| Bybit | `bybit` | `$DATA_ROOT/bybit` | `bybit-spot` 現貨、`bybit` 線性永續 | 支援 | 現貨 3 類、永續 5 類 |
| OKX | `okx` | `$DATA_ROOT/okx` | `okex` 現貨、`okex-swap` 永續 | 支援 | 現貨 3 類、永續 4 類 |
| Coinbase | `coinbase` | `$DATA_ROOT/coinbase` | `coinbase` 現貨 | 支援 | 現貨 3 類 |
| Upbit | `upbit` | `$DATA_ROOT/upbit` | `upbit` 現貨 | 支援 | 現貨 2 類 |

## 1. 選定交易所並建置共用映像

從 Git 專案根目錄開啟 Bash，在同一個終端執行後續命令。以下預設選擇全部五家。若只採集 OKX，可把陣列改成 `EXCHANGES=(okx)`。若採集兩家，可寫成 `EXCHANGES=(bybit upbit)`。商品與 channel 在建置前於設定檔中修改。[採集設定](01_collector/settings.json)

```bash
cd tardis_sample/step2
EXCHANGES=(binance bybit okx coinbase upbit)
export RUN_ID=smoke-001
export DATA_ROOT="$PWD/01_collector/output/raw/$RUN_ID"
docker compose -f 01_collector/compose.yaml config --quiet
docker build -f Dockerfile -t market-collector:local ..
```

`RUN_ID` 是這批資料的名稱。每次做新的短測，可改用 `smoke-002` 等新名稱並重新設定 `DATA_ROOT`。

## 2. 啟動 01 採集

### 每家 30 秒的首次驗證

```bash
for exchange in "${EXCHANGES[@]}"; do
  docker compose -f 01_collector/compose.yaml run --rm "$exchange" \
    python /app/step2/01_collector/01_collect.py cluster --exchange "$exchange" \
    --output /data --host-output "$DATA_ROOT/$exchange" --duration 30 || break
done
```

這個迴圈逐家執行。每家收訊 30 秒後會停止、排空並封存，再開始下一家。請在每家的 `$DATA_ROOT/<服務名稱>/` 查看 `manifest.json` 的 `status` 是否為 `stopped`、`raw_records` 是否大於零。原始分段位於 `raw/`。另看 `status.json` 的 `missing_required_sources` 與 `uncovered_gaps`，確認短測中觀察到的來源缺失及序號缺口。此時可直接使用下方匯出命令。

### 正式收集時同時啟動所選交易所

準備開始長期收集時，沿用步驟 1 的交易所清單，另外指定正式批次。

```bash
export RUN_ID=run-001
export DATA_ROOT="$PWD/01_collector/output/raw/$RUN_ID"
docker compose -f 01_collector/compose.yaml up -d "${EXCHANGES[@]}"
docker compose -f 01_collector/compose.yaml ps "${EXCHANGES[@]}"
docker compose -f 01_collector/compose.yaml logs --tail=30 "${EXCHANGES[@]}"
```

到收集終點再執行停止命令。若另開終端，請先回到 `tardis_sample/step2` 並設回同一組 `EXCHANGES`、`RUN_ID` 和 `DATA_ROOT`。

```bash
docker compose -f 01_collector/compose.yaml stop "${EXCHANGES[@]}"
```

也可只停止其中一家，例如 `docker compose -f 01_collector/compose.yaml stop okx`。該家排空後即可處理其完整批次，其他服務可繼續採集。

## 3. 五家交易所都可按需匯出原生 channel CSV

沿用要匯出的那一批 `RUN_ID` 和 `DATA_ROOT`。以下每次掛載一家交易所的輸入，並將各家的匯出游標分開保存。採集中可匯出已封存的 JSONL，排空後再執行同一命令即可補齊尾段。

```bash
mkdir -p "$PWD/01_collector/output/channels/$RUN_ID"
for exchange in "${EXCHANGES[@]}"; do
  docker run --rm --network none \
    --mount "type=bind,source=$DATA_ROOT/$exchange,target=/input,readonly" \
    --mount "type=bind,source=$PWD/01_collector/output/channels/$RUN_ID,target=/output" \
    market-collector:local python /app/step2/01_collector/01_collect.py export-csv \
    --input /input --output "/output/$exchange" || break
done
```

輸出依交易所、市場、商品、接收時間的 UTC 日期及原生 channel 存放。例如 OKX 現貨成交位於 `01_collector/output/channels/<RUN_ID>/okx/okex/BTC-USDT/<日期>/trades.csv.gz`，Upbit 則是 `upbit/upbit/KRW-BTC/<日期>/trade.csv.gz`。直接使用主機 Python 時，可執行同一入口，例如 `python3 01_collector/01_collect.py export-csv --input "$DATA_ROOT/bybit" --output "$PWD/01_collector/output/channels/$RUN_ID/bybit"`。[Python 依賴](requirements.txt)

## 4. 啟動 02，依交易所生成 Tardis CSV

等該家採集停止並排空後，直接讀取含有 `manifest.json` 的原始目錄，可跳過步驟 3。使用 `--exchange` 選擇一家交易所及其市場，包含該家的現貨及已支援的衍生品。輸出目錄須尚未存在。

| `--exchange` | 資料類型 |
|---|---|
| `binance` | 現貨及期貨皆有 trades、quotes、book_ticker。期貨另有 derivative_ticker、liquidations。 |
| `bybit` | 現貨及線性永續皆有 trades、quotes、book_ticker。永續另有 derivative_ticker、liquidations。 |
| `okx` | 現貨及永續皆有 trades、quotes、book_ticker。永續另有 derivative_ticker。成交取自聚合 trades。現有永續來源缺少指數價與清算。 |
| `coinbase` | matches、level2_batch、ticker 分別產生 trades、quotes、book_ticker。level2_batch 的合批會影響可觀察的報價變更次數。 |
| `upbit` | trade 產生 trades，orderbook 的完整快照產生 quotes。 |

在主機上單獨處理一家，例如 Bybit：

```bash
python3 02_normalize_tardis/02_normalize_tardis.py --exchange bybit \
  --input "$DATA_ROOT/bybit" --output "$PWD/02_normalize_tardis/output/$RUN_ID/bybit"
```

或使用步驟 1 建置的 Docker 映像，逐一處理所選交易所：

```bash
mkdir -p "$PWD/02_normalize_tardis/output/$RUN_ID"
for exchange in "${EXCHANGES[@]}"; do
  docker run --rm --network none \
    --mount "type=bind,source=$DATA_ROOT/$exchange,target=/input,readonly" \
    --mount "type=bind,source=$PWD/02_normalize_tardis/output/$RUN_ID,target=/output" \
    market-collector:local python /app/step2/02_normalize_tardis/02_normalize_tardis.py --exchange "$exchange" \
    --input /input --output "/output/$exchange" || break
done
```

在 `02_normalize_tardis/output/<RUN_ID>/<交易所>/<市場>/<類型>/<UTC 日期>_<商品>.csv` 查看結果，例如 `bybit/bybit-spot/trades/2026-11-25_BTCUSDT.csv`。每家輸出根目錄有自己的 `normalization_report.json`，同一目錄可作為 03 對帳的本地輸入。重跑請另選新目錄。

`--start-us` 為含起點，`--end-us` 為不含終點，兩者皆以事件時間的 epoch 微秒指定。窗前訊息仍用於建簿和更新行情狀態。`--recover` 可讀取已停止但未正常封存的批次。報告內 `status=complete` 表示重播完成，來源完整度需另查 `inputs[].health`、`source_limitations`、`mapper_issues` 與 `recovery_warnings`。

**使用 Docker named volume 時**，將步驟 3 或 4 的第一個 `--mount` 改成 `"type=volume,source=$COLLECTOR_VOLUME,target=/input,readonly"`。`COLLECTOR_VOLUME` 須對應所選交易所及該次批次，批量匯出時要逐家選對 volume。[Docker 部署指南](01_collector/DOCKER_DEPLOYMENT.md)


## 5. 使用 03 對帳

從同一工作目錄執行，並將 `START_UTC` 與 `END_UTC` 設為與 Tardis 參考資料重疊的 UTC 時間。

```bash
python3 03_compare/03_compare_tardis.py \
  --ours "02_normalize_tardis/output/$RUN_ID/binance" --tardis ../datasets \
  --start "$START_UTC" --end "$END_UTC" --output "03_compare/output/$RUN_ID/binance"
```

在對帳批次目錄查看 `comparison.json`。
