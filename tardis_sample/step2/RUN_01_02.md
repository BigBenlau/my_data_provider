# 從 01 採集到 02 生成 Tardis CSV

第一次使用可照以下三步完成一批 Binance 現貨與 USD-M 期貨資料。01 由一個 supervisor 和兩個 worker 採集原始 channel。02 在採集結束後直接重播 JSONL，略過原生 CSV 匯出。目前 02 支援 Binance 現貨與 USD-M 期貨。

## 1. 設定批次並建置映像

在已啟動 Docker 且可使用 `docker compose` 的主機，從 Git 專案根目錄執行。以下三步使用同一個終端。若要調整商品或 channel，建置前先修改 [settings.json](settings.json)。

```bash
cd tardis_sample/step2
export RUN_ID=smoke-001
export DATA_ROOT="$PWD/output/01_raw/$RUN_ID"
docker compose config --quiet
docker compose build binance
```

`RUN_ID` 用來對應這次採集與正規化的資料夾。重新做一批短測時，將它改為新的名稱，例如 `smoke-002`，並重新設定 `DATA_ROOT`。

## 2. 啟動 01，採集 30 秒

```bash
docker compose run --rm binance \
  python /app/step2/01_collect.py cluster --exchange binance \
  --output /data --host-output "$DATA_ROOT/binance" --duration 30
```

命令在前景運行。30 秒到時會停止收訊，待兩個 worker 排空、supervisor 封存資料並退出後，再執行 02。主機上的 `$DATA_ROOT/binance/` 應包含以下項目。

| 位置 | 如何判讀 |
|---|---|
| `manifest.json` | 正常結束時 `status` 為 `stopped`，`raw_records` 是已提交的原始筆數。 |
| `raw/` | 正規化使用的 JSONL 分段，可直接讀取 `.jsonl.gz`。 |
| `status.json` | 查看 `missing_required_sources` 與 `uncovered_gaps`，判斷短測中的來源缺失及缺口。 |

## 3. 啟動 02，離線生成 CSV

以下命令使用同一個映像，將剛才的 **Binance 批次目錄**以唯讀方式掛入。只建立輸出父目錄，`--output` 指定的批次子目錄必須尚未存在。重播相同資料時可改用新的輸出名，例如 `/output/smoke-001-replay2`。

```bash
mkdir -p "$PWD/output/02_tardis"
docker run --rm --network none \
  --mount "type=bind,source=$DATA_ROOT/binance,target=/input,readonly" \
  --mount "type=bind,source=$PWD/output/02_tardis,target=/output" \
  market-collector:local python /app/step2/02_normalize_tardis.py \
  --input /input --output "/output/$RUN_ID"
```

若 01 使用 Docker **named volume**，請將上述第一個 `--mount` 的內容換為 `"type=volume,source=$COLLECTOR_VOLUME,target=/input,readonly"`，其中 `COLLECTOR_VOLUME` 是該次 Binance 採集已使用的 volume 名稱。[部署與 volume 範例](DOCKER_DEPLOYMENT.md)

若原始資料在主機目錄，也可在已安裝 [requirements.txt](requirements.txt) 的 Python 環境中直接執行以下命令。這是同一個 02 步驟，兩種執行方式擇一。

```bash
python3 02_normalize_tardis.py \
  --input "$DATA_ROOT/binance" \
  --output "$PWD/output/02_tardis/$RUN_ID"
```

### 查看結果

主機輸出位於 `output/02_tardis/<RUN_ID>/`。例如 BTC 的期貨成交檔為 `binance-futures/trades/<UTC日期>_BTCUSDT.csv`。現貨有 `book_ticker`、`quotes`、`trades`，期貨另有 `liquidations` 和 `derivative_ticker`。當天沒有清算事件時，清算 CSV 可以只有表頭。

先讀同一目錄下的 `normalization_report.json`。`status` 為 `complete` 表示重播完成。`data_quality` 若為 `review_required`，對帳前應查看 `inputs[].health`、`mapper_issues` 和 `recovery_warnings`。

## 長期採集時如何接上 02

在步驟 1 所用的 `step2/` 目錄，為正式批次設定自己的名稱與資料路徑，再啟動背景採集。以下範例只開 Binance。

```bash
export RUN_ID=run-001
export DATA_ROOT="$PWD/output/01_raw/$RUN_ID"
docker compose up -d binance
docker compose logs --tail=30 binance
```

到預定的收集終點，再於相同目錄、相同 `DATA_ROOT` 下執行停止命令，等候排空。

```bash
docker compose stop binance
```

確認這批的 `manifest.json` 為 `stopped` 後，沿用 `RUN_ID` 和 `DATA_ROOT` 執行步驟 3。若五家交易所都有採集，02 的輸入仍指定這批的 `binance/` 子目錄。
